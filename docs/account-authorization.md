# 免手填 Token 的账户授权核验

日期：2026-10-15（北京时间）；来源敏感级别：公开。

目标：朋友在微信打开网页 → 一次麦当劳账户授权 → 选店与抽餐 → 确认 → 官方付款。用户不需要理解或手动申请开发者 Token。

## 当前结论

现有比赛 MCP 接入仍公开要求每位用户登录官方平台、激活并复制自己的 MCP Token，再用 Bearer 请求头调用。未找到可供本项目直接使用的第三方 OAuth、应用注册或授权回调文档；不能把在官方平台登录成功等同于第三方网页获得授权。

另找到官方商户开放平台，公开文档包含查询／更新／清空购物车与提交订单，但要求申请开发者准入、经审核分配账号、给应用申请接口权限，并使用麦当劳分配的 MerchantId、AppId、签名密钥。该文档没有说明第三方用户登录授权机制，也没有确认其购物车与官方 App／小程序购物车共享。因此这是需要官方对接确认的路线，不能认定拿到商户凭证就已实现消费者授权。

只读补充探测：`mcp.mcd.cn` 的 OAuth 受保护资源与授权服务器 well-known 地址返回 404；`open.mcd.cn` 对 OAuth/OIDC 发现路径返回 HTML 页面，不是 JSON 元数据。这只说明当次没有在这些标准地址发现 OAuth，不能证明官方没有其他非公开合作接口。

不变更当前线上账户流程，不制作没有真实授权能力的登录按钮，不代理收集麦当劳短信验证码或借作者账户替朋友下单。正式替换前需要官方确认：个人参赛项目可用的授权方式、应用准入、消费者权限、购物车归属与微信内支付路径。

主题：开发者挑战赛项目咨询：第三方账户授权与微信内点餐接入

您好，我们正在参加麦当劳开发者创新挑战赛，项目为“麦麦不纠结”：https://github.com/Sognotore/mcd-bujiejie 。用户选择预算或跳过后随机搭配一人餐，再确认并进入官方付款。

当前 MCP 的个人 Token 申请和粘贴流程不适合普通朋友使用，希望实现微信打开网页后，在麦当劳官方页面完成一次授权，返回本项目即可选餐下单。请协助确认：
