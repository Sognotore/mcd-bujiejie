# 官方待支付订单实施记录

2026-10-15 用户明确选择“采用官方下单付款流程”。授权范围为实现用户确认后的真实下单，不把随机抽取当成下单，也未授权本次测试随意创建订单。

已实现：个人 Token 临时连接、独立内存会话、门店与餐单查询、服务端保存精确候选、下单前两次最新试算、官方取餐方式选择、确认下单、付款链接和本会话查单。公开服务不加载作者 `.env`，不使用作者 Token 作为公众账户。现有 Skill 仍保持只读范围。

可靠性：同一草稿多确认页与同一确认页重复请求不产生重复订单；实际写调用发出后不自动重试；提交结果不明时锁住本次连接的后续下单并指引官方查单。确认金额变动需重新核对，创建结果金额不一致或缺失时保留订单号并阻止付款跳转。

验证：业务与浏览器采用模拟订单测试；官方实际创建与支付仍待用户主动选餐后进行，不在测试中自动执行。真实门店及下单前确认页另记在 verification.md。

公网：GitHub Pages 仍为静态演示。个人授权下单服务的临时 Cloudflare 隧道启动被自动审批拒绝，要求用户明确同意个人 Token 和订单请求经 Cloudflare 转发；审批问题已向用户说明，拒绝后暂停了该动作。用户随后明确同意 Cloudflare 临时隧道，获得具体第三方转发授权后再进行部署。公网下单状态以实际部署与授权结果为准。
