# 点餐衔接能力核验与建议

日期：2026-10-15（北京时间）。状态：用户已确认并完成网页待支付订单流程实现；接口定义已核验，实际测试停在确认前，未创建真实订单。

用户希望抽出的搭配能直接进入麦当劳，避免在 App 或小程序重复挑选商品。

## 官方能力

- 当日直接读取官方 MCP 完整工具清单共 35 项，没有名称或描述为购物车写入的工具；官方公开协议和工具表未找到带商品跳转 App／小程序购物车的说明。这不等同于断言所有合作渠道均无该能力。
- 官方 `create-order` 支持传入门店、就餐方式、商品编码、数量、精确特调及套餐组成；文档响应为待支付订单和 `payH5Url`。
- 到店自取使用 `beType=1`、`orderType=1`；`takeWayCode` 必须来自当次 `calculate-price` 返回的 `takeWayList[].code`，不能猜值。
- 官方工具描述指引用户通过支付链接扫码或打开麦当劳 App 完成付款；不能据此声称微信同一手机可直接付款，须验证实际生产支付页。

## 已确认产品流程

个人授权 → 选择门店 → 预算或跳过 → 随机搭配 → 确认门店、完整规格、份数及最新应付 → 用户点击“确认下单” → 创建官方待支付订单 → 官方付款 → 查询订单状态。

这能避免重新挑选餐品，但会创建真实待支付订单，按钮不能误标为“加入购物车”。抽取和重抽本身不创建订单。

个人会话后端已实现，每人使用自己的 Token，服务器内存有效期 30 分钟；官方现有文档展示的是个人 MCP Token 申请及使用流程，尚未核验可供此网页使用的第三方 OAuth。不能先承诺普通微信登录即可授权，也不能把作者 Token 当作朋友的共享账户。

实现下单时需重新核验价格、门店、规格与取餐方式；处理中禁用重复提交，超时不自动重发不确定的下单请求，保留明确订单状态再做支付跳转。演示搭配不能转成真实订单。
