# 麦麦不纠结 · 首版需求与设计

日期：2026-10-15（北京时间）  
状态：2026-10-15 用户已确认本书面设计并要求开始实施。  
项目：独立的 `mcd-bujiejie` 仓库。

## 1. 已确认的目标

用户原始需求：“选一个预算后（也可以跳过），随机搭配，解决选择困难的问题。”

用户已同意“网页＋Skill”的产品形态并授权开始。成功体验是：用户选预算或跳过，点击一次后得到一份可理解的一人餐搭配；不用再从多份推荐中做选择。

本设计将一人餐、预算上限、重抽和单品锁定具体化。默认一人餐、默认到店取餐、不自动创建订单是首版实现选择；不视为用户已经确认的长期产品决策。

## 2. 首版范围

- 网页：预算设置、抽一餐、结果展示、重新抽取、锁定单品。
- Skill：在支持 Skill 和麦当劳 MCP 的客户端中完成相同的决策流程，支持“30 元内帮我搭一餐”“不设预算”“饮料保留，其他重抽”。
- 两种明确的数据状态：可直接运行的演示模式，以及用户在本机配置凭证后的实时模式。
- 首版实时就餐方式固定到店取餐。首次选择门店，以后可复用或更改；只存门店标识及名称，不保存定位或地址原文。
- 下单不属于首版交付。结果可以复制为点餐清单；用户自行在官方渠道核对并点餐。

演示模式与实时模式沿用同一搭配规则。演示数据中的价格、餐品名称、门店和图片均不可标为当前官方数据；未配置或调用失败时不得悄悄回退成演示结果。

## 3. 网页流程

### 3.1 首页

标题：“麦麦不纠结”。主文案：“预算你定，吃什么交给它。”

预算快捷选项为 20、30、40、50 元，另有自定义金额和“跳过预算”。这些数值是预算选项，并非对套餐价格的承诺。首次进入默认不选中任何金额；主按钮为“帮我搭一餐”。未选择预算时，按跳过预算处理，页面明示“不限预算 · 一人餐”。

自定义预算只接受大于零、至多两位小数的金额。空白视为跳过；负数、零、非数字、超过两位小数均给出就地提示，不触发抽取。

首页不增加口味问卷、热量目标或人数选择。结果区域持续显示当前数据模式。实时模式需先完成门店选择；没有门店时，抽取按钮引导选择门店，不展示伪造的可售结果。

### 3.2 搭配结果

一次只展示一份搭配：一份主食、一份小食、一份饮品；一个官方套餐也可构成这一结构，但不能重复计入套餐内已包含的商品。

结果展示餐品名称、组成和价格依据。演示模式展示“演示合计”；实时模式展示经 `calculate-price` 确认的应付总价、优惠及必要费用。适用优惠券只以实际查到且试算成功的结果为准。

结果提供“换一份”“复制清单”，每个可替换组成项可锁定。复制清单必须带上演示/实时标识；实时结果还包含门店、取餐方式和试算时间。套餐内不可独立更换的项目不提供误导性的锁定操作。

### 3.3 重新抽取与锁定

- 重抽遵守原预算、门店和锁定条件。
- 有其他合法组合时，下一份不得与上一份完全相同。
- 锁定单品必须保留原规格和数量。
- 全部锁定后，“换一份”禁用并提示“先解锁一个餐品”。
- 没有其他合法组合时保留原结果，并提示“当前条件下只有这一份搭配，可以解锁餐品或调整预算”。
- 用户更改预算、门店、数据模式时，旧结果失效并清空锁定；不得保留一个已不满足条件的报价结果。
- 抽取期间禁用重复提交；晚到的旧请求不得覆盖新条件下的结果。

## 4. 搭配与预算规则

### 4.1 候选集

候选只来自当前模式的明确数据源。实时模式必须来源于选定门店当前菜单及必要的餐品详情，不使用模型记忆补齐缺失商品、规格、套餐组成、价格或库存。

先过滤不可售、无法定价或缺少必要选择项的餐品，再按主食、小食、饮品和已完整配置的套餐形成候选组合。官方类别、套餐组成和可替换选项需要以实际返回字段适配，不能仅凭名称猜测套餐结构。无法确定的商品不进入可保证预算的候选集。

### 4.2 预算

预算是最高可接受的最终应付金额，不是凑满预算的消费目标。内部金额一律采用整数分。

有预算时，完整组合的最终应付总价必须小于或等于预算。实时价格须由官方试算确认，涵盖返回的全部必要费用与适用优惠。返回缺少应付总价、金额格式错误、报价过期或试算失败时，该组合不得作为预算内结果展示。

跳过预算只取消金额上限；餐品份数及一人餐结构保持不变，不额外加购。

不存在预算内完整一人餐时，明确提示“当前预算下暂时搭不出完整一餐”。不自动提价、不减少为一杯饮料，也不未经请求改换门店。只有完整检查了当前候选集，才可声称“没有可行搭配”或给出最低可行金额；若仅达到实时试算次数上限，提示“暂未找到预算内搭配，可重试或调整预算”。

### 4.3 随机与试算开销

从满足结构和锁定条件的组合中随机抽取；候选足够时避免连续重复。随机目标是提供可接受的意外感，不宣称找到全局最低价或营养最优解。

完整枚举演示候选集并按预算过滤。实时模式先使用有来源的价格进行候选预筛，再随机试算；每次抽取最多发起 12 次官方价格试算，达到上限时返回“暂未找到”，不能误报“预算不可能”。当前请求内对完全相同的组合复用试算结果；条件变化或下一次抽取需重新确认价格。

正式展示前再次校验完整组合、锁定、去重与预算约束。价格来源、试算时间和错误原因必须能在脱敏日志中追溯。

## 5. MCP 接入设计

官方远程服务为 `https://mcp.mcd.cn`，采用 Streamable HTTP，以 Bearer Token 授权。Token 只从本机服务端环境变量 `MCD_MCP_TOKEN` 读取；不写入网页源码、浏览器存储、日志、Git 仓库或截图。

实时模式以官方 MCP 客户端 SDK 建立连接、读取工具清单和输入 schema，再适配以下已在官方文档列出的工具：

1. `query-nearby-stores`：按用户主动提供的位置查询附近门店。
2. `query-meals`：读取选定门店当前菜单。
3. `query-meal-detail`：确认套餐组成及必要可选项。
4. `query-store-coupons`：只读查询当前门店适用优惠券。
5. `calculate-price`：确认组合的应付总价。

工具名称、输入 schema、实际返回和测试门店已于 2026-10-15 完成授权实调，详见 `verification.md`。适配定义保存在代码中，运行时继续核对 schema，不将文档示例误当作当次可用字段。

首版不调用 `create-order`、领券、积分兑换或其他账户写工具。网页后端只开放上述本功能需要的只读工具，拒绝任意工具名转发。Skill 同样限定这些只读能力。

实时网页仅供用户在本机单人使用，服务默认监听 `127.0.0.1`，校验请求来源和请求体，不提供携带项目作者 Token 的公共代理。可公开展示演示模式；面向公众的个人授权体系不在首版范围。

## 6. 实现结构

使用原生 HTML/CSS/JavaScript 实现轻量网页，Node.js >=22.9 服务承载本机 API 与 MCP 适配。以官方 MCP SDK 处理协议，不自行拼凑不完整协议实现。具体依赖版本在开发开始时从官方来源核验并锁定。

目录边界：

- `web/`：页面、样式、浏览器交互与原创建图形。
- `src/domain/`：金额、结构、锁定和随机搭配规则，不依赖网页或 MCP。
- `src/providers/`：显式演示数据源与真实 MCP 数据源。
- `src/server/`：本机 API、工具白名单、输入校验和模式状态。
- `skills/mcd-bujiejie/`：可安装 Skill 及调用说明，共用需求和验收规则。
- `tests/`：验证关键业务约束和 MCP 失败路径的测试。
- `docs/`：本设计、实施计划、来源及验证记录。

页面保留一个视觉中心：预算与“帮我搭一餐”主按钮。使用温暖的米白、深色文字和明亮强调色；用原创建餐品插画表达随机搭配。不得将项目包装为官方产品，不从其他作品复制品牌素材。支持窄屏、键盘操作及减少动画偏好。

## 7. 错误与空状态

- 无凭证：实时模式提示“尚未配置连接”；用户可主动进入演示模式。
- 401：提示凭证无效或过期，不回显凭证。
- 429、超时、网络失败：保留输入，提示稍后重试，不展示虚构报价。
- 无附近门店：提示调整位置；不生成虚构门店。
- 菜单缺少一人餐所需类别：说明当前门店暂时无法搭配完整一餐。
- 官方 schema 或返回结构不兼容：中止实时推荐并报告接入状态，不通过猜字段继续。
- 锁定项不再可售：说明需解锁或重新选择，不替换为另一个名称相近的商品。
- 复制失败：保留可选中的文字清单，并提示手动复制。

## 8. 验收标准

1. 不配置 Token 也能启动演示网页，完整走通选预算、跳过、抽取、重抽、锁定、复制清单。
2. 演示金额与官方实时价格始终能明确区分；接口错误不触发隐式演示降级。
3. 批量验证随机结果均保持一人餐结构、整数分金额和预算上限；预算恰好等于应付金额时允许输出。
4. 验证自定义金额非法输入、预算不足、候选为空、只有一种组合、全部锁定和锁定后不可行。
5. 验证切换条件及并发请求时旧结果不会误覆盖，结果不会无声超支。
6. MCP 使用 mock 验证授权、工具白名单、超时、401/429、无效 schema 和最终试算上浮；这些测试不能替代官方实调。
7. 使用真实 Token 完成菜单、详情和计价调用，并保留不含个人信息的调用证据后，才能标记“实时接入已验证”。
8. 桌面和手机宽度检查布局，键盘能完成关键操作，减少动画偏好生效。
9. Skill 能按官方菜单和计价结果返回一份搭配，缺少条件时只追问必需信息，不编造菜单或价格。
10. 核验参赛规定文件完整、配置已脱敏、官方声明逐字一致；公开仓库和报名成功以实际平台结果为准。
